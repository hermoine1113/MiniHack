Q6. AWS – Cloud Deployment using EC2
Extra focus
The sample paper requires EC2, key pairs, security groups, SSH, Java, Maven, Tomcat, GitHub deployment, database connectivity and CloudWatch. Your uploaded AWS notes cover account creation but do not provide the full deployment commands below. These are practical Ubuntu EC2 steps to complete the SET-1 task.
1. Create EC2 instance – AWS Console
1. Open AWS Console → EC2 → Launch Instance.
2. Choose Ubuntu Server.
3. Select an instance type.
4. Create/download a key pair (.pem file).
5. Create a Security Group with these inbound rules:
Type	Port	Source
SSH	22	My IP
HTTP	80	0.0.0.0/0
Custom TCP	8080	0.0.0.0/0

6. Launch the instance.
7. Copy its Public IPv4 address.
2. Connect to EC2 from Windows CMD
Go to the folder containing your .pem file:
ssh -i "your-key.pem" ubuntu@EC2_PUBLIC_IP


Replace your-key.pem and EC2_PUBLIC_IP.
3. Update Ubuntu and install Java, Maven, Git and Tomcat
Run inside EC2:
sudo apt update
sudo apt upgrade -y


sudo apt install openjdk-17-jdk maven git tomcat9 -y


Check installations:
java -version
mvn -version
git --version


Start Tomcat:
sudo systemctl start tomcat9
sudo systemctl enable tomcat9
sudo systemctl status tomcat9


4. Clone GitHub repository
git clone https://github.com/kvrajanirajesh/mid2-ecommercemaven.git


Enter the project folder:
cd mid2-ecommercemaven


If the Maven project is inside mavenjava:
cd mavenjava


5. Build Java application using Maven
mvn clean
mvn compile
mvn test
mvn package


Check generated WAR file:
ls target


6. Deploy WAR file to Tomcat
sudo cp target/*.war /var/lib/tomcat9/webapps/


Restart Tomcat:
sudo systemctl restart tomcat9


Check status:
sudo systemctl status tomcat9


7. Access application
Open in browser:
http://EC2_PUBLIC_IP:8080


If the WAR file is named ecommerce.war, the application URL will usually be:
http://EC2_PUBLIC_IP:8080/ecommerce


8. Useful troubleshooting commands
sudo systemctl status tomcat9
sudo systemctl restart tomcat9
sudo journalctl -u tomcat9 -f
sudo ss -tulpn


9. CloudWatch monitoring
In AWS Console:
1. Open CloudWatch.
2. Select Metrics → EC2.
3. Select the EC2 instance.
4. View CPU Utilization and other available metrics.
5. Create an alarm for high CPU utilization.
For memory and disk metrics, install and configure the CloudWatch Agent. Attach the CloudWatchAgentServerPolicy IAM role to EC2 first.

For an Ubuntu x86-64 instance, the agent package can be installed with:
wget https://amazoncloudwatch-agent.s3.amazonaws.com/ubuntu/amd64/latest/amazon-cloudwatch-agent.deb
sudo dpkg -i -E ./amazon-cloudwatch-agent.deb


The agent also needs a configuration file specifying the memory and disk metrics to collect.
10. Database connectivity
- Configure the application's database URL, username and password.
- Ensure the database server is running and reachable from EC2.
- Allow the database port only from the EC2 security group or trusted private network.
- Do not expose the database publicly.

Three things to avoid losing marks:
1. Docker: use the same volume when recreating MySQL.
