# 3. What is `pom.xml`?

`pom.xml` = **Project Object Model**

It contains project/build information such as:

* Project name
* Group ID
* Artifact ID
* Version
* Packaging
* Dependencies
* Plugins
* Java compiler configuration
* Build configuration
* Final WAR/JAR name

Basic structure:

```xml
<project>

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>myproject</artifactId>
    <version>1.0</version>

    <packaging>war</packaging>

    <dependencies>
        ...
    </dependencies>

    <build>
        ...
    </build>

</project>
```

# 5. If `mvn` is not recognized

Error:

```text
'mvn' is not recognized as an internal or external command
```

### Check:

```bash
mvn -version
```

Possible reasons:

* Maven not installed
* Maven not added to PATH
* `MAVEN_HOME` not configured
* Terminal needs to be reopened

Then configure Maven's `bin` directory in Windows PATH.

Example:

```text
MAVEN_HOME = C:\apache-maven-...\

PATH = %MAVEN_HOME%\bin
```

Then reopen Git Bash/terminal:

```bash
mvn -version
```

# 9. Dependency conflict ⭐

Suppose:

```text
Library A → X version 1.0
Library B → X version 2.0
```

Maven has to select one version.

### Important exam point:

**Maven generally uses the nearest dependency in the dependency tree.**

You can explicitly specify the desired version:

```xml
<dependency>
    <groupId>com.example</groupId>
    <artifactId>X</artifactId>
    <version>2.0</version>
</dependency>
```

Then:

```bash
mvn dependency:tree
```

Verify the selected version.

### SET-1 extra

Dependency conflict is explicitly asked in HMS.

### SET-4 extra

Dependency tree is explicitly asked:

```bash
mvn dependency:tree
```

# 33. Git Reset ⭐

If commits are local and haven't been pushed, you may move the branch backward.

```bash
git reset --hard <commit-id>
```

Example:

```bash
git reset --hard a1b2c3d
```

### Difference:

| Command       | Meaning                                     |
| ------------- | ------------------------------------------- |
| `git revert`  | Creates a new commit that undoes old commit |
| `git reset`   | Moves branch pointer backward               |
| `git restore` | Discards file changes                       |

### SET-2 EXTRA

Reset to earlier local commit.

# 35. Fetch vs Pull ⭐

### Fetch

```bash
git fetch origin
```

Downloads latest remote information **without merging it into your current branch**.

### Pull

```bash
git pull origin main
```

Usually:

```text
fetch + merge
```

So:

```text
fetch = download/check
pull = download + integrate
```

# 45. Rebase workflow

First:

```bash
git fetch origin
```

Update/rebase:

```bash
git switch feature-branch
git rebase origin/main
```

Concept:

```text
Before:

main:    A---B---C
              \
feature:       D---E


After rebase:

main:    A---B---C
                  \
feature:           D'---E'
```

Your feature commits are replayed on top of latest main.

---

# 46. Rebase conflict

If conflict occurs:

```text
CONFLICT
```

Check:

```bash
git status
```

Open the conflicting file.

You'll see:

```text
<<<<<<< HEAD
main changes
=======
your changes
>>>>>>> feature
```

Edit the file and keep the correct content.

Then:

```bash
git add <file>
```

Continue:

```bash
git rebase --continue
```

Repeat until all conflicts are resolved.

# 53. Dockerfile for Maven WAR + Tomcat ⭐⭐⭐

For the basic lab:

```dockerfile
FROM tomcat:9.0

COPY target/*.war /usr/local/tomcat/webapps/ROOT.war

EXPOSE 8080

CMD ["catalina.sh", "run"]
```

### What each line means

```dockerfile
FROM tomcat:9.0
```

Uses Tomcat 9 image.

```dockerfile
COPY target/*.war /usr/local/tomcat/webapps/ROOT.war
```

Copies WAR into Tomcat.

`ROOT.war` means application is deployed at:

```text
/
```

```dockerfile
EXPOSE 8080
```

Documents the container's Tomcat port.

```dockerfile
CMD ["catalina.sh", "run"]
```

Starts Tomcat in foreground.

This is the Dockerfile pattern given in the lab instructions.

# PART F — MOST IMPORTANT DIFFERENCES TO MEMORIZE

## `restore` vs `revert` vs `reset`

| Situation                            | Command                      |
| ------------------------------------ | ---------------------------- |
| Discard uncommitted file changes     | `git restore file`           |
| Remove file from staging             | `git restore --staged file`  |
| Undo already committed change safely | `git revert commit-id`       |
| Move branch back to old commit       | `git reset --hard commit-id` |

### Easy memory:

```text
RESTORE → file
REVERT → committed change
RESET → move branch backward
```

---

# `fetch` vs `pull`

```bash
git fetch origin
```

→ downloads remote information only.

```bash
git pull origin main
```

→ fetch + integrate.

### Merge


Combines branches and preserves branch history.

### Rebase


Moves/replays your commits on top of latest main to create a cleaner history.

# PART I — DOCKERFILE TO MEMORIZE ⭐⭐⭐

For **WAR + Tomcat**:

```dockerfile
FROM tomcat:9.0

COPY target/*.war /usr/local/tomcat/webapps/ROOT.war

EXPOSE 8080

CMD ["catalina.sh", "run"]
```

Then:

```bash
mvn clean package
docker build -t HMS .
docker run -d -p 8080:8080 --name hmscontainer HMS
```

Browser:

```text
http://localhost:8080
```

The source instructions specifically emphasize that `EXPOSE 8080` does **not itself change the Tomcat port**; the `-p host:container` mapping is what makes the container reachable from the host.
